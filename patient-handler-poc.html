01

Intake & Scheduling on ConversationRelay

Replace the existing call runtime with ConversationRelay while keeping the agent's dialog, tools, patient-matching, scheduling, and transfer logic unchanged:

  1. Caller calls in.
  2. Agent determines patient intent / reason for call.
  3. Agent captures the relevant configured intake details, such as symptoms, medical conditions, medication names, personal details, and scheduling preferences.
  4. Agent repeats key information back accurately.
  5. Agent matches the patient.
  6. Agent searches appointment availability.
  7. Agent schedules or reschedules an appointment.
  8. Agent confirms appointment details back to the caller.

02

Deterministic Patient Matching on ConversationRelay

Extend the ConversationRelay agent to collect DOB, name, and phone from the caller with repeat-back and correction, then call the existing decision engine as a single tool call and act on its structured result (match, no-match, ambiguous, or transfer).

  1. Greeting is handled by the current agent.
  2. Current agent identifies a scheduling intent in the existing flow.
  3. Agent gathers DOB, name, and phone with repeat-back and correction, using ConversationRelay's native STT/TTS.
  4. Agent calls the existing decision engine as a single tool call and receives one of: match, no-match, ambiguous, or transfer.
  5. Agent branches on the tool result — continues to scheduling on match, clarifies on no-match or ambiguous, or hands to warm transfer.

The intake slice tests whether ConversationRelay's STT/TTS behavior can reliably collect and confirm DOB, name, and phone against a scripted set of scenarios: long pauses mid-utterance, mid-repeat corrections, caller barge-in during pre-rendered prompts, low-confidence names that need a spell-back turn, DTMF fallback when the caller taps digits instead of speaking, and ambiguous-match disambiguation.

The journey also covers using Twilio TTS for generic connective speech while using play for stable questionnaire prompts where useful. For example, if a primaryText prompt is stable, the audio can be pre-rendered or cached and delivered via a ConversationRelay play message rather than generating TTS live.

03
Process inbound ConversationRelay messages
The WebSocket server reads ConversationRelay's message types — setup, prompt, interrupt — and forwards the transcribed utterance to the existing agent runtime rather than to a new one.
relay/messageHandler.ts
import { WebSocketServer } from 'ws';
import { existingAgentRuntime } from '@customer/agent-runtime';
import { routeToExistingAgent } from './toolBridge';
import { sendAgentResponse } from './sendAgentResponse';

const wss = new WebSocketServer({ port: 8080 });

wss.on('connection', (socket) => {
  let callSid: string;

  socket.on('message', async (raw) => {
    const message = JSON.parse(raw.toString());

    switch (message.type) {
      case 'setup':
        callSid = message.callSid;
        break;
      case 'prompt':
        const reply = await routeToExistingAgent(callSid, message.voicePrompt);
        sendAgentResponse(socket, reply);
        break;
      case 'interrupt':
        existingAgentRuntime.cancelInFlightResponse(callSid);
        break;
    }
  });
});

import type { WebSocket } from 'ws';

export type AgentReply = { text: string };

export function sendAgentResponse(socket: WebSocket, reply: AgentReply) {
  socket.send(JSON.stringify({
    type: 'text',
    token: reply.text,
    last: true,
  }));
}
05
Re-invoke the existing tools after a response
When the agent's turn produces a tool call — patient matching, availability search, scheduling, or transfer — it's routed to the existing tool implementations, and the result is fed back into the same agent turn before replying to the caller.
relay/toolBridge.ts
import { existingAgentRuntime, existingTools } from '@customer/agent-runtime';

export type ToolCall = { name: string; args: Record<string, unknown> };

export async function routeToExistingAgent(callSid: string, utterance: string) {
  const result = await existingAgentRuntime.handleTurn(callSid, utterance);

  if (result.toolCall) {
    const toolResult = await invokeExistingTool(result.toolCall);
    return existingAgentRuntime.continueWithToolResult(callSid, toolResult);
  }

  return result;
}

async function invokeExistingTool(call: ToolCall) {
  switch (call.name) {
    case 'matchPatient':        return existingTools.matchPatient(call.args);
    case 'searchAvailability':  return existingTools.searchAvailability(call.args);
    case 'scheduleAppointment': return existingTools.scheduleAppointment(call.args);
    case 'transferCall':        return existingTools.transferCall(call.args);
    default: throw new Error(`Unrecognized tool: ${call.name}`);
  }
}

import { existingTools } from '@customer/agent-runtime';
import type { Intent, TenantConfig } from '@customer/tenant-config';

export function resolveTransfer(intent: Intent, tenantConfig: TenantConfig) {
  const rule = tenantConfig.transferRules.find((r) => r.matches(intent));
  return rule
    ? existingTools.transferCall({ reason: rule.reason, target: rule.target })
    : null;
}

Journey 2: Steps

ConversationRelayVoice
01
Switch ConversationRelay to Deepgram flux for the intake slice
Deepgram's flux speech model unlocks partialPrompts (unfinalized transcripts, so the agent can start fillers or tool calls before the caller has stopped speaking) and eotThreshold (confidence-based end-of-turn detection tuned for natural pauses between DOB month/day/year). Pair it with deepgramSmartFormat to receive DOBs, phone numbers, and dates already in canonical form, and interruptSensitivity: 'medium' to reduce false barge-ins during repeat-back.
voice/incoming.ts
import { twiml as TwiML } from 'twilio';
import { app } from './server';

const { VoiceResponse } = TwiML;

app.post('/voice/incoming', (req, res) => {
  const twiml = new VoiceResponse();
  const connect = twiml.connect();

  connect.conversationRelay({
    url: process.env.RELAY_WS_URL,
    welcomeGreeting: 'Thanks for calling — how can I help you today?',

    transcriptionProvider: 'Deepgram',
    speechModel: 'flux',
    partialPrompts: true,
    eotThreshold: 0.8,
    deepgramSmartFormat: true,

    interruptible: 'any',
    interruptSensitivity: 'medium',
    speechTimeout: 1200,
  });

  res.type('text/xml').send(twiml.toString());
});
02
Extend the agent's system prompt with an intake collection contract
Extend the Journey 1 agent's system prompt with an explicit contract for the intake slice: ask for DOB, then name, then phone; repeat each captured value back before advancing; on a "no" or a mid-utterance correction, re-ask that single field; call matchPatient only once all three are confirmed.
agent/intakePrompt.ts
export const INTAKE_CONTRACT = `
When the caller has a scheduling intent, collect the following before calling matchPatient:
  1. date of birth (month, day, year)
  2. full name (first and last)
  3. phone number (10 digits)

For each field:
  - ask for it in one short question
  - repeat back what you heard, digit-by-digit for phone, spelled-back for name
  - if the caller says no, corrects you, or interrupts, re-ask ONLY that field
  - advance to the next field only after an explicit or implicit yes

Once all three are confirmed, call matchPatient(dob, name, phone) exactly once.
Do not ask any other questions during intake.
`;
03
Expose the existing decision engine as a single tool
matchPatient is registered on the agent as a tool that takes the confirmed (dob, name, phone) tuple and returns one of match, no-match, ambiguous, or transfer. The tool's body forwards the call to the customer's existing decision engine and returns its verdict unchanged. 04
Deliver stable intake prompts via ConversationRelay play
Fixed intake prompts ("What's your date of birth?", "And your phone number?") are pre-rendered once, hosted at a stable URL, and delivered via ConversationRelay's play message so the caller hears identical audio every call. Connective speech continues to flow through the text path already wired in Journey 1.

import type { WebSocket } from 'ws';

const PROMPT_MEDIA = {
  askDOB:   'https://cdn.example.com/prompts/ask-dob.wav',
  askName:  'https://cdn.example.com/prompts/ask-name.wav',
  askPhone: 'https://cdn.example.com/prompts/ask-phone.wav',

export function playPrompt(socket: WebSocket, key: keyof typeof PROMPT_MEDIA) {
  socket.send(JSON.stringify({
    type: 'play',
    source: PROMPT_MEDIA[key],
    loop: 1,
    preemptible: true,
    interruptible: true,
  }));
}
05
Branch the agent's next turn on the tool result
Once matchPatient returns, its structured result is fed back into the same agent turn via Journey 1's continueWithToolResult. The agent continues to scheduling on match, asks a targeted clarifying question on no-match or ambiguous, or emits the existing transferCall tool on transfer.
agent/onMatchResult.md
# Guidance appended to the system prompt

After matchPatient returns, do exactly one of the following:

- match       → confirm the patient by first name and proceed to scheduling
- no-match    → apologise briefly, then re-ask ONE field the caller
                is most likely to have misheard (usually phone)
- ambiguous   → ask a single disambiguating question drawn from the
                candidates (e.g. "Are you the John Smith born in April
                or in August?")
- transfer    → call transferCall(reason) — do not attempt to schedule
06
Speak a filler while the agent is thinking
The instant a prompt arrives, send a short filler text message so the caller hears acknowledgement immediately, then start the LLM / matchPatient call in parallel and stream the real response when it arrives. Pick from a small rotation so it doesn't sound canned.
relay/fillerAck.ts
import type { WebSocket } from 'ws';
import { routeToExistingAgent } from './toolBridge';

export type PromptEvent = { voicePrompt: string; lang: string; last: boolean };

const FILLERS = ['Okay', 'Mm-hm', 'Got it', 'One moment'];
const fillerCursors = new Map<string, number>();

function fillerIndex(callSid: string) {
  const next = ((fillerCursors.get(callSid) ?? -1) + 1) % FILLERS.length;
  fillerCursors.set(callSid, next);
  return next;
}

export async function onPrompt(socket: WebSocket, callSid: string, event: PromptEvent) {
  const filler = FILLERS[fillerIndex(callSid)];
  socket.send(JSON.stringify({ type: 'text', token: filler + '. ', last: true }));

  const reply = await routeToExistingAgent(callSid, event.voicePrompt);
  socket.send(JSON.stringify({ type: 'text', token: reply.text, last: true }));
}
07
Re-prompt the caller when they go silent mid-intake
After each agent turn, arm a per-call silence timer. If the caller doesn't produce a prompt before the timer fires, gently re-ask the current intake field. Any inbound prompt, dtmf, or interrupt event clears the timer.
relay/silenceTimer.ts
import type { WebSocket } from 'ws';

const SILENCE_MS = 6000;
const timers = new Map<string, NodeJS.Timeout>();

export function armSilenceTimer(socket: WebSocket, callSid: string, currentField: string) {
  clearSilenceTimer(callSid);
  timers.set(callSid, setTimeout(() => {
    socket.send(JSON.stringify({
      type: 'text',
      token: `Are you still there? I just need your ${currentField}.`,
      last: true,
    }));
  }, SILENCE_MS));
}

export function clearSilenceTimer(callSid: string) {
  clearTimeout(timers.get(callSid));
  timers.delete(callSid);
}
08
Cancel in-flight generation when the caller barges in
When the caller starts speaking over the agent's TTS, ConversationRelay emits an interrupt message. Abort the in-flight LLM / matchPatient promise so the next prompt from the caller isn't answered with a stale reply from the previous turn.
relay/interruptCancel.ts
import type { WebSocket } from 'ws';
import { routeToExistingAgent } from './toolBridge';
import type { PromptEvent } from './fillerAck';

const inFlight = new Map<string, AbortController>();

export async function onPrompt(socket: WebSocket, callSid: string, event: PromptEvent) {
  const controller = new AbortController();
  inFlight.set(callSid, controller);
  try {
    const reply = await routeToExistingAgent(callSid, event.voicePrompt, { signal: controller.signal });
    socket.send(JSON.stringify({ type: 'text', token: reply.text, last: true }));
  } catch (err) {
    if ((err as Error).name !== 'AbortError') throw err;
  } finally {
    inFlight.delete(callSid);
  }
}

export function onInterrupt(callSid: string) {
  inFlight.get(callSid)?.abort();
}
09
Accept DTMF as a fallback for intake fields
If the caller taps digits instead of speaking (noisy environment, accessibility), dtmf messages arrive one digit at a time. Buffer them into the current field and submit when the expected length is reached — 10 digits for phone, 8 for DOB (MMDDYYYY).
relay/dtmfBuffer.ts
import { submitFieldFromDtmf } from './intakeState';

const buffers = new Map<string, string>();
const EXPECTED = { phone: 10, dob: 8 } as const;

export function onDtmf(callSid: string, digit: string, currentField: keyof typeof EXPECTED | null) {
  if (!currentField) return;
  const next = (buffers.get(callSid) ?? '') + digit;
  buffers.set(callSid, next);

  if (next.length === EXPECTED[currentField]) {
    submitFieldFromDtmf(callSid, currentField, next);
    buffers.delete(callSid);
  }
}

BonusVoiceConference
01
Decide when to escalate to a human
A single decision function inspects the current state — the last matchPatient tool result, an agent-side escalation signal, or an explicit caller request — and returns whether to begin warm transfer. Automated turns are suppressed once it fires.
warm-transfer/detectHandoff.ts
import type { CallState } from './callState';

export type HandoffDecision = { reason: string };

export function shouldWarmTransfer(state: CallState): HandoffDecision | null {
  if (state.lastMatchResult?.kind === 'transfer') return { reason: state.lastMatchResult.reason };
  if (state.agentSignal === 'escalate')           return { reason: 'agent-escalation' };
  if (state.callerRequestedHuman)                  return { reason: 'caller-request' };
  return null;
}
02
Build the handoff context the agent's Voice SDK will receive
Decide which caller-side attributes the human agent needs at pickup and produce a compact object of them: call SID, reason, the matchPatient verdict kind, a patient reference on match, and a short last-utterance snippet. Twilio's guideline is under 800 bytes total for custom parameters, so send references (SIDs, IDs) rather than payloads — no full transcript. The encodeHandoffParams helper turns the object into a URL-safe string ready to append to To=client:{id}?… in the bridge step.
warm-transfer/handoffContext.ts
import { callStateStore } from './callState';
import type { HandoffDecision } from './detectHandoff';

export type HandoffParams = {
  callSid: string;
  reason: string;
  matchKind: 'match' | 'no-match' | 'ambiguous' | 'transfer' | 'none';
  patientId?: string;
  lastCallerUtterance?: string;
};

export function buildHandoffParams(callSid: string, decision: HandoffDecision): HandoffParams {
  const state = callStateStore.get(callSid);
  const last = state.transcript.at(-1);
  return {
    callSid,
    reason: decision.reason,
    matchKind: state.lastMatchResult?.kind ?? 'none',
    patientId: state.lastMatchResult?.kind === 'match' ? state.lastMatchResult.patientId : undefined,
    lastCallerUtterance: last?.text?.slice(0, 200),
  };
}

export function encodeHandoffParams(p: HandoffParams): string {
  const entries = Object.entries(p).filter(([, v]) => v != null) as [string, string][];
  return new URLSearchParams(entries).toString();
}
03
Bridge the caller and agent, attaching handoff context to the agent's leg
Move the caller into a Conference (hold music via waitUrl), then dial the human agent into the same Conference. The handoff object from step 02 rides on the agent's To=client:{id}?…: Twilio delivers each key as a custom parameter on the incoming call in their Voice SDK, so their client opens the call already grounded. A Say announce plays on the agent's leg before their audio joins the caller.
warm-transfer/bridge.ts
import Twilio from 'twilio';
import { TWILIO_NUMBER, AGENT_IDENTITY } from './config';
import { briefing } from './agentRouting';
import { buildHandoffParams, encodeHandoffParams } from './handoffContext';
import type { HandoffDecision } from './detectHandoff';

const twilio = Twilio(process.env.TWILIO_ACCOUNT_SID!, process.env.TWILIO_AUTH_TOKEN!);

export async function bridgeToAgent(callSid: string, decision: HandoffDecision) {
  const conf = `warm-${callSid}`;

  await twilio.calls(callSid).update({
    twiml: `<Response><Dial><Conference waitUrl="/hold">${conf}</Conference></Dial></Response>`,
  });

  const params = buildHandoffParams(callSid, decision);
  const to = `client:${AGENT_IDENTITY}?${encodeHandoffParams(params)}`;

  await twilio.calls.create({
    to,
    from: TWILIO_NUMBER,
    twiml: `<Response><Say>${briefing(decision)}</Say><Dial><Conference>${conf}</Conference></Dial></Response>`,
  });
}
04
Keep the caller informed during the bridge
The Conference's waitUrl serves a short spoken announce ("Connecting you to a scheduler — this will take just a moment") followed by hold music. If the wait exceeds a threshold, a follow-up reassurance prompt plays. Silence is what makes callers hang up — a scripted play loop prevents it.

import { twiml as TwiML } from 'twilio';
